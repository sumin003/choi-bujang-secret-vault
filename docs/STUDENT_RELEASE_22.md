## 문제 수정·최종 커밋 관리

코드나 실행 도구가 바뀌면 새 커밋을 만들고, 해당 커밋으로 별도 폴더를 맞춘 뒤 관련 절차를 다시 확인합니다. 다른 커밋의 통과 결과를 합쳐 최종 전체 성공으로 표시하지 않습니다.

이번 후속 변경은 문서 세 개뿐이며, 실제 앱 코드·설정 견본·잠금 파일의 기준 커밋 대비 바이트 일치를 Git 트리로 확인합니다. 문서 포함 제출본 자체의 확인은 별도 폴더에서 새 커밋을 가져와 고정한 뒤 최소 실행·메뉴·종료·재실행 결과를 재확인해야 합니다. 아직 그 후속 확인은 미실행입니다. 이 때문에 현재 릴리스는 검증 중입니다.

후속 커밋 값은 생성 후 별도로 안내합니다. 실제 값을 확인한 뒤 다음 형식으로 고정하며, 이 문서에는 모르는 미래 해시를 추정해 넣지 않습니다.

~~~powershell
git fetch origin
git switch --detach <실제_문서포함_40자리_커밋>
git rev-parse HEAD
~~~

위 꺾쇠 부분을 그대로 실행하지 않습니다. 코드가 없는 예시가 아니라 Git 명령의 자리표시자이며 실제 값을 안내받고 치환합니다. 서버가 켜져 있으면 먼저 해당 재현 서버를 Ctrl+C로 끕니다. 기존 개인 인증을 삭제하거나 재승인·유료 요청을 반복하지 않습니다.

## 21·22단계 원문 제출과 미완료 사항

프로젝트 Git 최상위에서 제출할 실제 HEAD와 변경 목록을 확인합니다. 21·22단계는 현재 과제 안내에 따라 저장소 URL과 40자리 커밋을 직접 입력합니다. 비공개 저장소를 공개로 바꾸지 않습니다. 비공개 원문이 필요하면 과제 화면의 원문 전달 도구를 프로젝트 밖에 풀고 출력 JSON용 새 폴더도 프로젝트 밖에 준비합니다.

student-source-cli.mjs의 구체 명령은 과제 화면에서 받은 실제 옵션을 따르고 --commit에 실제 제출 해시를 지정합니다. 제공받지 않은 옵션·도구 경로를 만들어 쓰지 않습니다. 도구는 커밋 원문을 묶는 것이며 학생 코드 실행·업로드·공식 통과가 아닙니다. 같은 단계에서 JSON을 선택하고 저장소·커밋·단계를 확인한 뒤 사용자가 제출합니다. 원문 전달만 실패하면 기존 접수를 보존하고 원문만 다시 보내기를 사용합니다.

현재 남은 항목은 문서 포함 후속 커밋 재현, 새 폴더의 단계별 실제 기능 확인, 실제 AI·SDP·OSV 연결, 실제 학생 조치 결과(UNV), 다른 PC/OS·백업 복원 검증입니다. 운영 집행기 구축이나 운영자 자격 발급을 학생에게 요구하지 않으며, 그 기능을 전체 완료 범위에서 지우지도 않습니다. 실제 제출·유료 요청·보안 조치는 이번 문서 작성에서 실행하지 않았습니다.
