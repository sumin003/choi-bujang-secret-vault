# 12단계 정상·금지 요청 확인 절차와 결과표

이 표는 저장소의 1~11단계 계약을 정리한 **자체 점검 계획 41행**입니다. 제공된 심판의 공식 41종 목록은 저장소에서 확인되지 않았으므로 동일한 목록이라고 주장하지 않습니다. 공식 목록을 받으면 시험 번호·요청·기대 결과를 그 목록과 대조합니다.

기존 배포를 대상으로 직접 HTTP 점검을 시도합니다. 실행 결과는 아래 표의 해당 행에만 기록합니다. 이전 로컬 자동 시험이나 과거 사용자 확인을 이번 배포 API 결과로 옮기지 않습니다.

## 기존 배포에서 실행

커밋·재배포 없이 저장소 터미널에서 `node scripts/stage12-http-check.mjs`를 실행합니다. 첫 화면·정적 메모 제거·배포 식별·보안 헤더·미로그인 메모 요청 다섯 행만 실제 요청하며, 같은 표와 `artifacts/stage12-http.json`을 갱신합니다. 서버 응답의 요청 ID가 없으면 미제공입니다. 통신 실패·플랫폼 차단·HTML 오류를 자료 API 거부로 통과시키지 않습니다. 이 실행은 로그인 사용자의 본인 메모 허용을 대신하지 않습니다.

보호 자료 정상 허용은 기존 배포에서 승인된 브라우저와 A 계정으로 로그인한 뒤 개발자 도구 Network의 `GET /api/notes`를 확인해 T08에 기록합니다. 200과 본인 자료만 반환되는지 확인하고, 응답 본문은 복사하지 않습니다. B로 로그인한 뒤 A 자료의 GET·PUT·DELETE 거부도 해당 행에 따로 기록합니다. 계정 비밀번호·토큰을 이 문서나 명령 인자로 전달하지 않습니다.

## 기록 순서

1. 배포 주소, `/aleph.json`의 커밋과 단계, 시험 환경을 표 위에 기록합니다. 기존 데이터 대신 삭제 가능한 가상 시험 메모를 준비합니다. 복원은 검증된 B 시험 사본 한 건이 준비된 경우에만 실행합니다. 준비되지 않으면 미실행입니다.
2. 한 행씩 실제 요청을 보냅니다. 브라우저에서는 개발자 도구 Network에서 **해당 요청의** 메서드·경로·상태 코드·응답 헤더를 확인합니다. 새로고침이나 요약 API 조회만으로 다른 행을 실행한 것으로 처리하지 않습니다. 표에는 계정을 A/B로만 적고 자원 ID는 가명으로 치환합니다.
3. 실제 API 결과에는 HTTP 상태와 허용 목록의 오류/이유 코드·자료 유무만 적습니다. 메모 제목·본문, 이메일, 사용자 UUID, 비밀번호, Cookie, Authorization, JWT, 서버 키, 원본 요청/응답 전체는 복사하지 않습니다. 복원 내용은 서버 내부에서 ID·소유자·내용 해시를 비교하고 표에는 일치 여부만 남깁니다.
4. 요청 ID는 서버 응답의 요청 식별자(예: 서버가 실제 반환한 X-Request-ID 또는 플랫폼의 X-Vercel-ID)를 **헤더 이름과 함께** 적습니다. 없으면 ‘미제공’으로 적고 생성하거나 추측하지 않습니다. 확인 시각은 실제 응답을 확인한 ISO 8601 시각과 시간대입니다. 미실행에는 ID·시각을 채우지 않습니다.
5. 같은 요청 ID의 서버 기록에서 비밀값을 제외한 수치·상태·이유만 대조합니다. 화면 수치, 해당 API 응답, 가린 서버 기록이 모두 같을 때만 일치를 기록합니다. 대응 기록이나 식별자가 없으면 ‘대조 미확인’입니다. `/api/operations`의 저장된 fixture 집계는 실제 사건 수나 이번 시험 통과 건수가 아닙니다. 12단계 요약 API는 서버가 만든 요청 ID를 X-Request-ID 헤더·응답·화면·서버 JSON 로그에 함께 넣습니다. Vercel Logs에서 event=operations_summary와 해당 요청 ID로 찾아 summary의 규칙·집계·회수/복원 상태·시각을 응답과 대조합니다. 로그는 허용 목록의 요약만 담으며 사용자·토큰·쿠키·메모 원문은 전달하지 않습니다. 플랫폼 로그 수집·보존과 배포 대조는 별도 확인 대상입니다.
6. 판정기·탐지·정책 파일 시험은 HTTP API 시험과 구분합니다. 실제 API 결과 칸은 ‘해당 없음(로컬 가상 시험)’으로 적고 실행 명령·실제 출력·확인 시각을 별도 근거로 기록합니다. 없는 HTTP 요청 ID를 만들지 않습니다. 실제 회수·재로그인 연결이 없는 환경은 해당 집행을 미실행으로 둡니다.
7. 기대 결과와 실제 결과 및 데이터 불변 조건까지 확인한 행만 통과로 바꿉니다. 기대와 다르면 실패, 요청했지만 응답·기록을 확인하지 못하면 미확인, 보내지 않았으면 미실행입니다. 통과/실패/미확인/미실행을 따로 집계하며 총합이 41이어야 합니다. 정상 허용과 금지 거부를 모두 확인해야 합니다. 금지 요청은 허용되는 응답으로 오인하지 않도록 자료가 없는지도 확인합니다.
