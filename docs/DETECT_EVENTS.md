# 9단계 탐지 연습 사건 계약

`npm run detect:test`는 학생이 작성한 `src/detect.mjs`의 `detect(events)`에 가상 조회 사건을 전달합니다. 제공된 기존 시험 사건은 다음 세 값을 가집니다.

```js
{ at: '2026-10-01T00:00:00.000Z', method: 'GET', identity: { sub: 'learner_fixture' } }
```

## 입력 처리의 선택 메타데이터

가명 사용자·기기·요청 종류·판정만 읽는 제작 요청에 따라 입력 처리 함수 `readDetectionEvents(events)`는 아래 선택 항목도 지원합니다. 기존 시험 사건은 그대로 허용합니다. 이는 학습 입력 처리의 확장이며 운영 엔진에 새 사건 전달 계약이 생겼다는 뜻은 아닙니다.

| 항목 | 입력 검사 |
| --- | --- |
| `identity.sub` | 가명 사용자 식별자만 복사하며 이름·이메일·토큰은 읽지 않음 |
| `deviceId` | 있을 때만 16자리 소문자 16진수 기기 식별자 검사·복사 |
| `deviceRegistered` | 있을 때만 boolean 검사·복사; 회수 제안에는 true 확인 필요 |
| `method` | 대문자 GET·POST·PUT·PATCH·DELETE·HEAD·OPTIONS 중 하나 |
| `decision` | 있을 때만 allow·deny·step_up 중 하나 |
| `at` | 기존 계약의 UTC ISO 시각을 시간 계산용 메타데이터로 유지 |
| `signals.source` | 선택 가상 신호의 출처: judge_fixture 또는 none |
| `signals.network` | 선택 네트워크 신호: usual·unusual·unknown |

`deviceId`·`deviceRegistered`·`decision`은 사건 자신의 항목일 때만 읽습니다. 없으면 생략하고, 잘못된 값이 있으면 `invalid_detection_events`로 거부합니다. 헤더·중첩 기기 객체·역할·토큰에서 값을 보충하지 않습니다. 메모 내용·인증정보·실명 등 추가 필드는 읽거나 복사·저장·출력하지 않습니다. 입력 객체도 변경하지 않습니다. 입력 형식 검사는 출처 인증을 대신하지 않으며 호출자는 검증된 가상 사건만 전달해야 합니다. `decide(request)`의 기존 18항목 계약은 변경하지 않습니다.

## 복합 탐지 규칙

제작 요청의 “평소와 다른 네트워크와 갑작스러운 다량 조회가 함께 나타날 때만”을 적용합니다. 같은 `identity.sub`의 GET 중 `signals.source: judge_fixture`와 `signals.network: unusual`인 사건이 어느 10분 구간에서든 **120건을 넘으면** 의심 사건입니다. 회수 제안은 그중 같은 `deviceId`와 `deviceRegistered: true`가 확인된 사건만 따로 세어, **한 기기에서 독립적으로 120건을 넘을 때만** 생성합니다.

이 결과는 `decide(request)`의 접속 허용/거부 응답과 별도입니다.

```js
{
  action: 'propose_revocation',
  reasonCode: 'burst_read',
  subject: 'learner_fixture',
  deviceId: '0123456789abcdef'
}
```

대상은 문자열 deviceId 한 개이며 subject는 기기의 가명 사용자 문맥입니다. 사용자 전체·여러 기기에 대한 회수가 아니고, 다른 정상 기기를 대신 선택하지 않습니다. 기기 확인 정보가 없거나 미등록이거나 여러 기기 합산만으로 기준을 넘으면 `{ action: 'alert', reasonCode: 'burst_read', subject: '해당 sub' }`로 의심을 표시하며 회수 제안을 만들지 않습니다. 여러 확인 기기가 각각 기준을 넘더라도 한 번의 호출은 대상 한 개만 제안합니다.

이는 로컬 가상 사건용 별도 제안 형식이며 운영 엔진의 집행 계약을 확인한 결과가 아닙니다. deviceRegistered의 boolean 값이나 judge_fixture 표시만으로 실제 출처를 인증할 수 없으므로, 호출자가 엔진이 검증한 사건만 전달해야 합니다. 회수 API를 만들거나 호출하지 않으며, 기기 등록부·허용/거부 규칙·사용자 권한을 변경하지 않습니다. 실제 회수 여부와 완료 시각은 심판이 확인합니다. 완료 시각이나 소요 시간을 코드가 임의로 기록하지 않습니다.

복합 의심 조건도 넘지 않으면 `{ action: 'observe' }`입니다. 정확히 120건, 낯선 네트워크만 있는 사건, 평소 네트워크의 다량 조회, 지역 차이만 있는 사건은 제안 대상이 아닙니다. 다른 사용자의 사건을 합산하거나 10분 밖의 사건을 같은 묶음으로 세지 않습니다. 사건 순서가 섞여 있어도 사용자·기기별 시각을 정렬해 시간 구간을 검사합니다. 기존 시각·건수 기준과 네트워크 복합 조건은 보존합니다.

이 네트워크 항목은 이번 로컬 가상 사건 규칙의 선택 입력 확장입니다. 제공된 원래 세 항목만 있는 사건도 읽지만 네트워크 근거가 없어 observe로 남깁니다. 신호 출처나 네트워크 값이 없으면 추측해서 채우지 않습니다. source가 none이면 unusual이라는 값이 있어도 의심 근거로 사용하지 않습니다. signals의 지역·본문·토큰 등은 읽거나 저장하지 않으며 브라우저 헤더·위치 정보로 신호를 보충하지 않습니다. judge_fixture 표기는 실제 네트워크나 사건 출처를 인증하는 수단이 아닙니다.

이 파일의 사건 모양은 **로컬 연습용**입니다. 브라우저가 보낸 사용자 번호를 신원으로 취급하지 않습니다. 운영 반 엔진이 검증한 사건을 전달하고 회수 제안을 집행하는 경로는 별도로 연결·시험해야 합니다. 이 명령의 통과를 실제 접속 차단이나 심판 판정으로 표시하지 않습니다.
