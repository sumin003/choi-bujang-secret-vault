# 케셰브 완성본 시연과 확인 결과

작성일: 2026-10-29 (한국 시각). 이 문서는 화면 시연 순서와 확인 근거를 구분하는 학생 작성 문서입니다.
화면 틀은 관제 대시보드형(상태 카드 네 개, 아래 추이와 기록), 실행 형태는 포장 없이 프로젝트 폴더에서 실행입니다.
포장 명령·새 포장 스크립트·공격 시험·실제 보안 조치·유료 AI 설명 요청은 이 시연에서 실행하지 않습니다.

- 저장소: https://github.com/sumin003/choi-bujang-secret-vault
- 브랜치: main
- 문서 작성 시 대조한 앱 코드 커밋: 9df17a3582932a40a30644ecce68ddb9c21d7d8b
- 이 문서 추가는 문서만의 변경입니다. 실제 제출 커밋은 제출할 PC에서 git rev-parse HEAD로 확인합니다.
- 커밋은 원문 식별 근거이며 실행 성공 증거 자체는 아닙니다.

- 사용자 보고·사용자가 제공한 실제 앱 캡처·과제의 예시 화면을 구분합니다. 과제 예시 그림의 수치를 실측으로 쓰지 않습니다.
- 최신 가로 배치와 탭 종료·새로고침 시 추이 초기화는 2026-10-29 사용자가 직접 확인했다고 명시한 결과입니다. 별도 캡처나 터미널 출력이 없는 부분은 사용자 진술로 남깁니다.

## 실행 준비부터 종료까지

처음 받는 사람은 [최상위 README](../README.md)의 ZIP 다운로드·Node.js 준비 절차를 따릅니다.
기존 작업 폴더·이전 제출물에 ZIP을 덮어쓰지 않습니다. 개인 인증·설정 파일을 다른 PC로 복사하지 않습니다.
ZIP 실행에는 Git이 필수는 아니지만 커밋 확인·원격 갱신은 Git으로 받은 프로젝트에서 합니다.

기존 Git 프로젝트 최상위 PowerShell에서:
```powershell
git status --short
git log -1 --oneline
git rev-parse HEAD
```

최신 코드가 필요한 경우 변경 내용을 보존한 뒤 git pull --ff-only origin main을 사용합니다. 중단되면 원인을 확인하며 강제 push·초기화를 하지 않습니다.

탐색기에서 프로젝트의 on-client 폴더를 열고 주소창에 powershell을 입력합니다. package.json과 tools/start-alekov.ps1이 있는 위치인지 확인합니다.
```powershell
node --version
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

브라우저에서 http://127.0.0.1:5189/ 를 엽니다. 코드를 갱신했다면 Ctrl+F5를 누릅니다.
앱 서버가 열린 사실과 SDP·AI 연결은 별개입니다. 기본 시연에 -Demo를 붙이지 않습니다.
종료는 서버를 실행한 터미널에서 Ctrl+C입니다. 같은 on-client에서 같은 명령으로 재실행합니다.

## 핵심 기능 세 가지 시연

### 1. 기록 보기

1. 제공 화면의 ‘보안 기록’ 메뉴를 마우스 또는 Tab·Enter로 엽니다.
2. 실제 입력에 기록이 있으면 학생 영역의 기록 종류·업무 앱·접속 상태 필터를 하나씩 바꾸고 전체로 되돌립니다.
3. 화면에 실제 존재하는 ‘<사건 ID> 상세’를 열어 사건 ID·시각·종류·앱·요약, 근거 ID/글, 규칙 ID/글과 접속·세션·기기 상태를 확인합니다.
4. 기록이 없으면 빈 목록을, 조회 실패면 오류 이유를 그대로 보여 줍니다. 미연결 환경에 event-01이나 XDR 경보가 반드시 있다고 안내하지 않습니다.

시연 설명: “조회와 입력 검증은 제공 기능이고, 필터·정렬·상세 표시가 학생 작성 부분입니다. unknown은 확인 불가입니다.”
현재 실제 보안 기록 연동 성공은 확인되지 않았습니다. 과거 event-01 상세 확인은 예제(demo) 자료 확인이며 현재 실제 기록 성공으로 합치지 않습니다.

### 2. 내 PC 상태

1. ‘보호 현황 → 학생 상태·알림 표시 → 케셰브 · 내 PC 실측’으로 이동합니다.
2. ‘다시 조회’를 눌러 조회 중 표시 뒤 CPU·메모리·디스크·방화벽 카드 네 개를 확인합니다.
3. CPU 사용률(%), 메모리 사용량/전체(GiB, %), 디스크 남은 공간/전체(GiB, 여유 %), 방화벽 프로필 켜짐·꺼짐과 측정 묶음 시각을 읽습니다.
4. 다시 조회를 한 번 더 누르면 CPU·메모리 추이가 가로로 나란히 나타납니다. 좁은 화면에서는 세로로 바뀝니다. 직전 대비 CPU %p·메모리 GiB 차이를 확인합니다.
5. ‘측정 기록 보기’를 펼쳐 같은 값·정확한 시각·실패 이유를 표와 대조합니다.
6. 첫 조회만 있을 때 추이 안내만 표시되는지, 새로고침 후 이력이 초기화되는지 확인합니다. 탭 종료 후 재진입에서도 이력이 남지 않습니다.

시연 설명: “PC 측정은 제공된 읽기 전용 API입니다. 카드·가로 막대·최근 20회 추이·비교·기록 표·실패 안내는 학생 작성 부분입니다.”
추이는 조회 순서별이며 일정한 시간 간격을 뜻하지 않습니다. 실패 구간은 빈 구간이며 0·이전 값·예시 값으로 채우지 않습니다.

### 3. 위험 관련 알림과 연결 상태 읽기

이 항목은 시연용 분류이며 별도의 공격 탐지 기능이나 새 메뉴 이름이 아닙니다.
1. 학생 영역의 ‘연결과 기록’에서 네트워크 인터페이스·IPv4 주소 개수, 방화벽 프로필, Windows System·Application 경고·오류 합산 건수를 확인합니다.
2. Windows 조회 시작·측정 시각과 최대 5,000건·생략 여부를 읽고 “이 건수는 침해나 공격 탐지 결과가 아닙니다”를 설명합니다.
3. 아래 SDP 상태를 별도로 읽습니다. 명시적 미연결만 SDP 미연결이고, 근거가 부족하면 확인 불가와 이유입니다. PC 조회가 성공했다고 SDP가 연결됐다고 말하지 않습니다.
4. 기존 학생 알림 영역에 실제 전달된 resource·code·message를 확인합니다. 알림이 없으면 그 사실을 설명하고 새 경보를 만들지 않습니다.
5. 권한 부족이면 확인 불가 이유를 보여 줍니다. 관리자 실행·방화벽 변경·침투 시험으로 값을 만들지 않습니다.

시연 설명: “조회·알림 생성은 제공 기능이고, 상태 요약·안전한 문구·PC와 SDP 구분은 학생 작성 부분입니다.”

|---|---|---|
| 실제 앱 캡처 | 사용자 PC 카드에서 CPU·메모리·디스크 값·단위·측정 시각, 방화벽 프로필 표시 | 캡처 순간의 값이며 항상 같은 값이 나오는 것이 아님 |
